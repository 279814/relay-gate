# 维护与交接

更新日期：2026-10-18。需求基线仍为 [docs/01](01-需求与设计.md)，历史阶段记录见 docs/04–09。本文件记录当前实现、验收边界与后续维护入口，不替代需求。

## 项目与核心规则

仓库是 `279814/relay-gate`，Go + SQLite 单副本 LLM 中转网关；前端 Alpine.js 由 `go:embed` 内嵌，无独立构建链。

- 代理保持 Anthropic / OpenAI 原生协议；默认仅调整目标、认证和显式模型映射，Transform 须显式绑定。
- Upstream Reachability、Endpoint Capability、RouteHealth 分开归约，端点配置错误不能伪装成模型死亡。
- 真实请求已向客户端提交响应后不得换站重放；半开恢复受每 Route single-flight 保护。
- Lazy 不发送合成探活；paused / maintenance 控制真实流量与合成任务，不能靠 UI 开关代替后端门禁。
- 观察结果按发送前固定的 Observation Token / order 提交；迟到结果不能覆盖新配置或较新的观察。
- 旁路扫描、观察和持久化应有界，不能因数据库繁忙拖住真实转发；不完整观察不能声称 supported。
- 真实凭据、私有上游地址、未脱敏样本与在线能力矩阵不进入仓库或镜像构建上下文。

## 2026-10-18 维护内容

维护基于 GitHub `main` 的 `cf3b020` 开始；本地旧分支及未跟踪工作文件保留，修改在独立 worktree 进行。

1. Go 最低版本与 Docker builder 升至 **1.26.9**。旧工具链 1.26.5 的 `govulncheck` 命中 15 项可达标准库漏洞；升级后扫描为 0 项可达漏洞。依据：[Go 官方发布记录](https://go.dev/doc/devel/release)。
2. Bash / PowerShell 安装器向 Compose 查询实际发布端口，避免自行解析 `.env` 造成优先级错误；探活有超时，无效映射会失败退出；Linux 安装脚本保留执行位。
3. 首次凭据日志命令使用 `--no-log-prefix`，避免服务名前缀阻止匹配。
4. P5 私有文件门禁使用 `git ls-files -z`，修复默认 `core.quotePath=true` 时中文能力矩阵被转义而漏检的问题；回归使用真实临时 Git 索引验证。
5. CI 纳入前端模块契约、固定版本漏洞扫描、Linux / Windows 安装器行为测试；保留 Linux 竞态与容器端到端检查。Dependabot 每周检查 Go、Actions 和 Docker 依赖，通过 PR 与 CI 审核更新。
6. README、贡献指南、安全策略与阶段说明校正样本加密、主密钥轮换、HTTP 监听范围及 schema 7 事实。
7. 真实 `count_tokens`、结构化 `model_not_found` 与发送前本地配置错误复用统一观察队列和 `ResultRecorder`；发送前固定 token/order，提交后刷新能力状态，配置错误可跨重启保留。旧配置、复用 ID、较新人工重测与观察容量耗尽均有回归保护；真实转发不等待观察 worker 或数据库，观察准备不会因配置缓存刷新等待 SQLite。
8. Route / Upstream 重新启用时，在原事务递增已有 capability / network revision，拒绝上一生命周期的迟到结果；提交后的内存回填再核对现有健康世代。priority、weight、显示名称等编辑保留原语义版本，重新启用不会额外触发合成探活。

## 可复验命令

使用 `go.mod` 指定的 Go；验证环境另需 Bash、Python 3、Node.js 和 PowerShell 7。以下均为离线检查，不会请求真实上游：

```bash
go build ./...
go test -count=1 ./...
go vet ./...
go mod verify
node internal/web/bindings.check.js
node internal/web/app.contract.test.js
node --test internal/web/modules.contract.test.mjs
python scripts/deploy.contract.test.py
bash scripts/check-p0.sh
bash scripts/check-p5.sh
sh scripts/check-entrypoint.sh
sh scripts/check-deploy.sh
```

Linux 启用 CGO 后补跑 `go test -race -count=1 ./...`；漏洞扫描使用 `go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...`。安装器回归在临时目录执行真实脚本，仅替换 Docker / HTTP 边界，不启动容器、不接触已有 `data/`。容器实际行为由 GitHub CI 的 `container` job 验证，本机没有 Docker 时不能将静态检查写成容器验证通过。

隔离二进制运行验收 **66/66 通过**（Go 1.26.9），覆盖首次凭据生成、未授权拒绝、HTTP / SSE 代理、模型与认证改写、样本正文信封、管理员重新认证、主密钥轮换与重启后的暂停状态；额外验证 `count_tokens` 从 supported 遇 gzip 401 变为 config_error、本地估算仍正常、模型健康不受影响、重启继续保留错误。Route / Upstream 重新启用后均回到 unknown，新真实请求成功恢复 supported，期间无额外 HTTP / TCP 探活。只使用临时数据和本地假上游，不代表真实站点兼容性或生产压测。

部署与安全维护已通过 [PR #366](https://github.com/279814/relay-gate/pull/366) 的完整 CI：Linux race、重复测试、容器与双平台安装器全部成功，合并后的 `a799137` 主分支检查也通过。核心写回修复本地全量 `go test -count=1 ./...`、build、vet 与针对旧结果/配置变化/资源释放的回归已通过，远端验证以该修复 PR 与最终合并 SHA 的 CI 为准。

## 后续维护与发布

每次从最新 `main` 建 `codex/` 分支；在独立 worktree 开发，显式 pathspec 暂存。缺陷先复现、补测试，再最小修复；提交前检查是否过度设计、是否带入私有文件，以及文档是否仍符合最终行为。GitHub 操作使用 `gh` CLI，通过 PR 检查后合入。

发布前必须确认目标 SHA 的 Go / 竞态 / 前端 / 安装器 / 容器 / 漏洞检查全部通过，按需求执行在线兼容矩阵并保存脱敏结果，列明仍 Deferred 的范围，再创建对应 tag 与 Release。在线探活须显式使用 `--online --accept-probe-cost`；原生 control 重放还需 `--accept-control-replay`，不能因日常维护而自动使用本地私有输入或发送计费请求。

升级、迁移和轮换前先停止服务并整体备份数据目录与 `secrets/`；备份后启动服务，再走管理界面的密钥轮换流程。旧环境变量迁移步骤见 [docs/06](06-P2-部署与管理安全.md)，离线恢复步骤见 [README](../README.md)。不要把代码回退当数据库降级；按 manifest 的 reader contract 与配对程序恢复。
