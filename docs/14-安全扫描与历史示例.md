# 安全扫描与历史示例

更新日期：2026-10-18。固定 Gitleaks 8.30.1，下载产物与官方 release 的 SHA-256 配对校验。执行 `python scripts/check-secrets.py --gitleaks /绝对路径/gitleaks --self-test` 会先证明一个全新提交的合成 canary 被拒绝，再扫描 `git --all` 可达历史。输出只有规则、路径、行号和 fingerprint，不回显匹配文本或密钥。

首次扫描覆盖 482 个提交、约 6.43 MB 内容，命中 20 项：11 项来自仓储/代理测试与本地冒烟脚本的合成凭据；9 项来自已删除的历史部署文档。历史文档以保留的 example.com 域名和文档示例 IP 演示部署，但把随机生成的 Master、Relay、管理密码写成固定示例并在命令中重复使用。这些值已公开，不能作为实际部署凭据；曾照抄使用的部署需要轮换相应凭据。没有向外部服务发送这些值检查其是否有效。

`.gitleaksignore` 列出上述已逐项复核的 20 个精确历史 fingerprint，以及 2026-10-19 被动扫描新增的 1 个明确标记为 SYNTHETIC 的有限证据哈希测试夹具 fingerprint，包含提交、路径、规则和行号。没有忽略整个测试目录、文档目录或某类密钥；新提交的新命中仍会失败。例外不代表旧演示值受到保密，也不代表已替任何实际部署执行轮换。

PR #401 压缩合并后，同一合成有限证据夹具在主分支提交 `7df586020ab9c4a07e23492f517fc1e171da4bff` 的第 109 行再次被历史扫描发现。逐项核对为同一明确标记的合成值后，补充此精确 fingerprint；一个夹具对应原分支与主分支两个历史指纹，未扩大规则或路径例外。

此扫描只读取 Git 已提交的内容，不读取私有 `.local/p0/`、真实上游输入、当前运行数据或用户未跟踪文件。Git / Docker 忽略和 P5 真实索引门禁另行保护备份、Keyring、私钥与本机抓包路径。历史扫描无法证明工作区之外或未跟踪的文件没有秘密，也不能替代实际部署的凭据管理。

没有改写共享 Git 历史。后续发现真实已用凭据时，先撤销/轮换，再按协作者影响制定历史清理方案；单纯删除最新版文件不会撤销凭据。

CI 同时以固定 Trivy 0.76.0 扫描两个实际生产镜像的 OS 与语言依赖，遇到已有修复的 HIGH/CRITICAL 项失败。首次镜像扫描发现 Alpine 3.21.8 基础层仍带 OpenSSL 3.3.7-r1，命中 CVE-2026-84782；[Alpine 官方安全数据库](https://secdb.alpinelinux.org/v3.21/main.json)列出 3.3.7-r2 修复。两个 Dockerfile 在安装依赖前升级当前发行分支的安全修订，之后重新扫描。该门禁没有声明所有低等级或尚无修复的漏洞为零；Go 可达漏洞另由 govulncheck 检查。

公网镜像还发现 urllib3 与 pip 内置副本的高危命中。实际下载并按 SHA-256 校验 pip 26.2.1 wheel 后检查 `pip/_vendor/vendor.txt`，确认它仍内置 msgpack 1.1.2、urllib3 2.7.0、setuptools 70.3.0；只升级同名顶层包不会替换这些副本。最终仅用带 wheel 哈希的 requirements 固定 Certbot 需要的 urllib3 2.8.0，移除固定 webroot 运行并不依赖的 pip 安装器，再用 `uv pip check` 和真实 Certbot 能力/插件探测验证兼容性。没有通过忽略这些漏洞使门禁变绿。
