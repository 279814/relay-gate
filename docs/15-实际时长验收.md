# 实际时长验收

`scripts/verify-duration.py` 使用真实网关进程、全新临时数据库和 loopback 假上游，读取真实单调时钟；不请求任何在线模型或使用私有输入。报告记录程序版本、二进制 SHA-256、实际秒数、请求/错误计数和进程资源样本。`/healthz` 的构建版本必须等于报告的源码 revision。

先把当前 Git revision 注入 `main.version` 编译二进制，再运行脚本。需要 Python 3 与 PowerShell 7；资源采样使用操作系统进程统计，包含 RSS、私有内存、句柄、线程与 CPU 时间。报告不包含首次凭据、请求正文和运行日志。

```text
python scripts/verify-duration.py --binary /绝对路径/relay-gate --mode long --seconds 2105 --source-revision <构建revision> --report /绝对路径/long.json
python scripts/verify-duration.py --binary /绝对路径/relay-gate --mode soak --seconds 172800 --source-revision <构建revision> --report /绝对路径/soak.json
```

长流门禁要求连续超过 35 分钟，逐字节保持 SSE 的语义事件、每 5 秒心跳和正常终止；测试会显式将真实请求总上限提高到测试时长加 120 秒，默认产品配置仍为 30 分钟。结束后在途计数必须归零，RSS 峰值不得超过 512 MiB。短于门槛的调用只标记 `short_contract_only`，用于快速验证脚本，不能充当长流通过记录。

本项目将多日持续运行的验收窗口定为 48 小时。soak 每约半秒执行一个真实假上游请求，错误计数须为零，每 30 分钟验证一次暂停拒绝与恢复，定期记录资源。进程连续运行，30 分钟暖机后的 RSS 拟合斜率不超过 2 MiB/小时、峰值不超过 512 MiB、句柄波动不超过 32、线程峰值不超过 128。它是明确的工程验收计划，不是既有需求规定了某个固定小时数。

`duration_gate_passed` 仅表示这个脚本的持续时长与资源判据通过，不代表整个版本已验收。轮换、取消、崩溃恢复、升级前后兼容及真实公网边缘仍需相应专项记录；已有短时二进制脚本不能代替这些持续运行记录。最终发布必须重新核对报告与最终目标 revision，不能把早期开发版本或加速时钟的结果当最终版本的多日验证。

临时进程和数据库在正常结束时清理。报告采用原子替换，运行中保留最新采样；采样空档超过 120 秒会失败，不能把主机休眠计入持续运行。进程中断、报告显示 running 或时长不足，均不能标记验收通过。48 小时任务应在可持续供电、可控的主机上执行。

## 真实 Nginx 边缘长流

`Public edge duration acceptance` 是独立手动工作流，使用与生产相同的固定Certbot/Nginx镜像及本地CA。
它在真实TLS连接上连续运行2105秒，每5秒写入心跳，验证首事件及时到达、全部原始SSE字节和正常结束。
随后仍执行续期失败、过期关门与关闭孤儿worker的既有回归。普通PR只运行短时同一测试；手动长流不随每次提交重复消耗35分钟。

```text
gh workflow run edge-duration.yml --ref <已推送分支或tag>
gh run list --workflow edge-duration.yml
gh run view <run-id> --log
```

工作流须先存在于默认分支后才能dispatch。日志绑定checkout SHA与实际镜像ID，并打印真实时长、心跳数和逐字节判据。
这项证据覆盖真实Nginx/本地CA，不能代替公网ACME签发或网关本身的48小时报告；最终验收须针对最终目标提交运行。
