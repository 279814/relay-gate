## 已交付

1. `internal/security`：结合协议角色/工具位置、代码围栏、HTML/登录/广告、敏感指令、外链、隐藏 Unicode 和已知 Credential 的本地组合规则。合法脚本单项只记低等级线索；手动 `ScanText` 共用引擎。原始首尾副本保留 offset 和缺口，重叠窗口不跨缺口制造事件。
2. `security.Center` / `PersistentCenter`：有界 finding 环 + SQLite `security_finding` 持久化。schema 10 新增 `truncated` / `decode_depth` / `evidence_hash`，哈希只覆盖有限脱敏证据；独立 9→10 预备份、精确旧 reader 与 schema 10 还原合同均有回归。
3. **真实流量旁路**：`proxy.Handler` 通过透明观察器复制原始上游 header/chunk，只有客户端实际写出 body 后才入有界队列；重试丢弃、count_tokens fallback 和零字节拒写不扫描。样本关闭或健康观察器未安装时仍可采集；Transform 输出不作为上游证据；准入/队列丢弃不阻塞转发并由后台记录计数告警。
4. API：`GET /admin/api/security/findings`、`POST /admin/api/security/scan`、`POST /admin/api/security/canary`（显式一次，Lazy 允许；共享 Executor 的独立严格诊断）、`GET/PUT /admin/api/security/canary-policy/{upstream_id}`（默认关闭、revision CAS，只有启用的 Active 目标可开周期）、`GET/PUT /admin/api/security/smtp`、`POST .../smtp/test`。
5. SMTP：`AlertMailer` 元数据模板（无对话正文）；强制验证证书的 STARTTLS / SMTPS，真实本地 TLS 服务器测试。schema 13 分别保存 `aggregation_window_sec` 与 `rate_limit_window_sec`，默认各 300 秒、范围 1–86400；PUT 必须带已读取的正 `expected_revision`。并发冲突 409 不修改密码或运行配置；UI 保留草稿并要求显式重载。测试邮件每次确实发送，不受告警开关、级别或去重抑制。
6. Security Center：schema17固定保存捕获的 `upstream_id/rule_id`、独立审核决定与最多1024条忽略规则。Findings按严重级别、捕获身份、类别、时间、审核、忽略状态进行SQL稳定游标分页，count与page在同一读事务；历史身份未知不会从当前配置猜补。`PUT /security/findings/{id}/review` 只接受 open/false_positive 与已有正 revision；忽略策略只支持 rule/route 单一目标、0明确永久、正值未来到期，更新/删除用CAS且ID不重用。冲突保留草稿并禁止自动重试。
9. 邮件忽略策略在后台直接读取同一 SQLite，发送前重新检查已排队项目；SQL/网络均在 Mailer 锁外。Rule/Upstream/Route 分别参与去重，pending/成功限流/在途身份共同有界1024。失败不占成功窗口、不丢失待聚合项；`GET /security/alert-status` 提供本次进程的策略失败、投递失败、容量丢弃和抑制计数。测试邮件继续每次实际发送，不受忽略策略与其读取故障阻断。
10. 原始证据：`GET /security/findings/{id}/evidence-metadata` 只读关联元数据；`POST .../evidence` 要求有效 Cookie 和本次管理员口令，并在首字节前完成持久审计。只接受可信 passive finding 的精确 ReqID + Route + Upstream 唯一样本尝试、schema15原上游完整视图；未知/未留样/重复尝试/扫描不完整/响应截断或省略均 unavailable。只读原有样本，不复制正文到finding。UI先展示可用性、再认证，关闭/登出丢弃迟到响应，已知UTF-8用纯文本显示，压缩或非UTF-8字节明确显示Base64。
11. `GET /security/diagnostics` 与 `GET .../{execution_id}` 只读取 Canary14 已持久事实和同一 ProbeExecution，按source/verdict/捕获Upstream/Route做有界SQL分页；普通旧manual不推断成Canary。运行仍使用共享Executor，手动Route停用沿用既有配置CAS与route_disable审计。UI `security.mjs` / `security_management.mjs` 保持纯文本。
7. 默认扫描 1 MiB 解码后正文；SSE/NDJSON 单事件 256 KiB；旁路 gzip/br 有界解压；Base64/URL/Unicode 最多两层、累计 4 MiB；Go RE2 单模式 4 KiB，另以程序指令数×窗口字节限制单次匹配工作量。执行预算为 100 ms 单调时钟保守预算，并有确定性字节/工作边界；截断、失败、上下文未知或耗尽均记可解释 incomplete。
8. schema 14 保存 Canary 的随机 nonce 哈希、唯一 inert tool 期待、严格 verdict 和手动/周期来源；不保存 nonce 原文或输出正文，不执行工具，不自动改变健康。等待协议正常结束和有界响应 EOF；额外输出、错误 nonce/工具、取消、不完整与未发送分别保留。成本复用原幂等事件门禁与 730 日水位，写入独立 daily；`/probe-statistics?basis=canary` 按真实来源分页，usage 缺失为 unknown、已观测 0 为 0，不生成 Recipe 成功率。详见 [Canary 设计与验证](specs/2026-10-19-canary-design.md)。
