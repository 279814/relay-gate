# P4 声明式转换实施记录

- 基线：`docs/01-需求与设计.md` §15、§20.5
- 状态：本分支已补齐下列管理合同及本地组合、浏览器证据；最终版本的 CI、公网及多日验收仍以[需求证据缺口](19-需求证据缺口.md)为准。

## 已交付

1. `internal/transform` 编译器：拒绝任意脚本迹象、头名/头值 CR/LF/NUL、受保护头最终控制、超限正则（RE2）。应用点对脏行再次拒绝，不得把注入字节写进出站 Header。
2. 请求规则：`set_header` / `delete_header` / `rename_header` / `replace_bytes` / `set_json_pointer`（顶层优先偏移替换）；应用后强制恢复 Authorization 等保护头。
3. JSON Patch 子集：`json_patch_add` / `json_patch_remove` / `json_patch_copy`（RFC 6902；可能重序列化；无 move/test/脚本引擎）。
4. 完整 body 模板：`body_template`（声明式字面量替换；拒脚本；不得删除/改类型/重复顶层 string model）。
5. Secret 引用污点：`secret_ref` 与 `{{SECRET:name}}`；渲染明文记入 `TaintBag`，不得进入预览/差异/执行记录/错误文本；执行记录剥离占位符名。
6. 执行预算：默认请求/响应 50ms、SSE 事件 10ms；可下调；**提高**需 `confirm_raise` + 审计记录；Apply 按墙钟强制；管理 UI 二次确认。
7. 非流式响应：同上 + `set_status`；默认 `fail_open` 回退原始状态/头/body。
8. SSE：按完整事件原子 `sse_match`；`sse_append_end` 标记 synthetic completion。
9. 生命周期：draft → preview → shadow/publish 指针 → rollback；在途请求不改已选版本（指针模型）。
10. shadow 只在副本上算脱敏差异摘要，不改真实请求。
11. 未绑定：`PublishedCompiled` 返回 nil，调用方不得进入转换路径（哈希恒等测试）。
12. 管理 API：`/admin/api/transforms*`、`transform-bindings`、`transform-executions`、`transforms/budgets`；main 装配 Registry。
13. **SQLite 持久化**（schema 6）：`transform_set` / `transform_version` / `transform_binding`；Registry `PersistSink` 在变更时整表快照，启动 `LoadFromPersist`（进程重启后仍可加载已发布绑定）。
14. **proxy 接线**：已发布绑定应用于出站请求、非流式响应与 SSE 事件；未绑定透传；请求 `fail_closed` 为 route-local（不发上游、不烧 `retry_max_attempts`，跳下一 Route；无候选时 502）；响应 `fail_closed` 在写入客户端前失败时回滚半截头/body 并返回本地错误；响应 `replace_bytes` / JSON pointer 与请求路径同样受 `MaxAddedBytes` 约束。
15. **管理 UI**：`transforms.mjs` + `index.html` 转换页（不改脏 `app.js`）。
16. **压缩请求显式重编码**（§6.7）：在草稿勾选“允许压缩请求改写”，发布后由无参数 `request_reencode` 规则授权该 Route+Endpoint；gzip/br 解压、映射、转换后按原编码发送，工作正文和编码产物各最多8 MiB。默认/其他Endpoint/Shadow绑定不授权真实改写，头规则不能伪造实际编码。count_tokens与模型请求共用准备函数但保留独立超时和本地估算。
17. **模型保护层**（§15.3）：请求规则后恢复Route模型并再次验证唯一字符串；删除、重复或非字符串按版本失败策略处理。普通/gzip/br实际HTTP模型覆盖回归已红→绿，旧隔离测试改写普通正文来持续验证实际Transform效果。
18. **请求快照与边界**：PR #393固定整条请求的版本/预算，本轮显式授权也受该快照约束；真实HTTP publish/rollback四组合、重试独立映射/凭据、未出网严格绑定不消耗半开且后续半开仍重查停用，均已定向验证。
19. **版本化管理**（schema16）：Set 与 Binding 独立客户端 CAS；发布/Shadow 同时校验，首次绑定显式版本0；停用、启用、不可逆归档和不可变历史回滚。Store 在同一事务校验目标存在及所属关系，提交失败不安装候选配置。普通配置 SQL 不持有请求读锁，预算通过既有 setting 行版本跨重启保留。
20. **有界管理页**：转换集、绑定和版本历史默认50、最多200；SQL 计数与当前页共用事务，列表不拉取完整规则。页面冲突保留草稿，显式重载；一次仅一个写请求，旧读取不覆盖新结果，激活待处理阻断重放。实际 Chromium 发布两版、Shadow、回滚首版后 SQL 指针一致且历史仍3条，见 [浏览器证据](evidence/transform-browser-bce5bc2.json)。此前双页面冲突、生命周期及预算确认见 [前轮证据](evidence/transform-browser-35099c2.json)。
21. **执行诊断分页**：沿用有界内存 ring，仅本次运行当前保留范围；支持 Route/Endpoint/Version、模式、阶段、结果及毫秒时间过滤，默认50、最大200。`GET /admin/api/transform-executions` 返回 `executions/total/next_cursor/limit/scope`（scope固定为`current_run_retained`），筛选参数为`route_id/endpoint_id/version_id/mode/phase/ok/after_ms/before_ms`。筛选绑定游标，锚点淘汰或重启后400要求重查；不冒称持久化完整历史。实际55条预览诊断50→5及阶段过滤通过。
