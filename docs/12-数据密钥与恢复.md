# 数据密钥与恢复

更新日期：2026-10-18。本记录描述 schema 8 的实际存储和恢复契约；最终验收仍须对应合并提交的 CI 与运行记录。

## 存储与迁移

Sample 与 Security 各有一个独立随机 Data Key，由 Master Key 包装保存在数据库中。正文的 v2 / 分帧 v2m 信封认证用途、数据密钥 ID；分帧格式还认证对象 ID、总长度和帧序号，拒绝截断、调序和替换。Master Key 轮换只重包 Data Key 及直接加密的上游、SMTP、Probe Secret、legacy URL；样本和安全证据正文保持不变。数据库的路径、查询、脱敏头等元数据并非整库加密。

schema 7→8 先验证旧数据并创建一致备份，再于同一事务内生成数据密钥、迁移旧明文与 v1/v1m、验证新信封并提交。任何坏密文都会拒绝迁移，不会把损坏密文当明文重包。正常 schema 8 读取只接受认证格式；启动会用当前 Master 重新解包 Data Key 并验证加密状态，不能借内存缓存或已退役旧 key 掩盖未完成轮换。

旧单块 v1 AES-GCM 验证需要该块的完整缓冲；v1m/v2m 按帧处理。迁移成功不等于旧备份、WAL、SQLite 空闲页和底层磁盘副本已安全擦除。应按原有敏感数据保留和删除策略管理它们，不能直接删除尚未验证的恢复副本。

## 备份单位与配对 reader

自动备份目录包含数据库、manifest，以及存在凭据目录时的 `secrets.json`。manifest 记录数据库和凭据归档的 SHA-256、大小、源 schema、配对 build 和 reader contract。文件按 0600、目录按 0700 创建；Windows 权限语义仍受本机 ACL 管理。`secrets.json` 保存真实 Master 与凭据文件的可恢复内容，编码不构成加密，必须保密。

schema 7 切换备份的默认配对源码为提交 `605a935031423e1afe8ce85aab0e19313ecad2af`，reader 为 `schema-7-reader`；明确传入的配对身份保持不变。schema 8 reader 为 `schema-8-data-key-v2-reader`。`relay-gate-schema-8-data-key-v2` 是当前构建身份标记，不是已发布的 Git tag。恢复前须准备 manifest 对应的程序，不能只回退代码并让旧程序打开新 schema。

## 离线检查与恢复

按 [README](../README.md#离线备份检查与恢复) 停止服务、保留整个数据目录，然后执行 `db check-backup`。它校验路径、reader、Master 配对、归档哈希和加密内容，不迁移、不改写数据库和 Keyring；SQLite 读取活动 WAL 时可能更新 SHM 的读者标记，不应把它描述成文件系统绝对零写入。

默认使用当前配置的 Master。需要恢复轮换前的备份时，显式增加 `--use-backup-keyring`，程序才会选择该备份中经过验证、与 manifest 配对的稳定 active Master；不会猜 pending key，也不会自动退回归档密钥。`db restore` 仍要求 `--execute --accept-data-replacement --accept-reader-contract '<精确 reader>'`。

恢复使用持久 intent，先隔离旧数据库和旧凭据，再安装验证后的数据库与 `secrets/`。进程中断后，服务在实例锁内、首次凭据 bootstrap 之前续做；发现损坏 intent、错 key、错哈希、越界路径或损坏正文会失败退出。隔离目录保留供核验，不能把它当可公开日志或提交到 Git。自定义 `RELAY_DB` 数据目录也受 Git / Docker 忽略规则与发布索引门禁保护。

## Master Key 轮换

API 的顺序为维护与管理写入 fence、真实请求 drain、后台队列屏障、一致备份及旧备份校验、prepared、数据库重包、pending 全量验证、激活、active 全量验证、cleaned。主程序必须装配真实 quiescer；没有装配时拒绝轮换，不能用空函数宣布写入已收敛。生产装配与最终长流联合验证纳入最终完成矩阵。

环境变量非空时仍优先于 Keyring。只要 `ENCRYPTION_KEY` 覆盖仍存在，UI/API 就会拒绝 Master 轮换，避免下次启动用旧环境密钥打开新库。先执行 `credentials migrate`，移除旧 `ENCRYPTION_KEY`、`RELAY_KEYS`、`ADMIN_PASSWORD`，重启并验证后再轮换。恢复 journal 先验证数据库和持久 Relay 凭据再推进阶段，失败保持维护与可恢复 key，不伪造回滚成功。

定向回归覆盖正文 UPDATE 拒绝触发器下的轮换、新 Master 单独冷启动、错误 key/缺失 DEK/坏分帧、旧 v1m 迁移、迁移事务回滚、DB+secrets 恢复中断、归档 key 显式选择、未装配与环境覆盖拒绝、管理写入竞争及 FIFO Flush。完整验证以目标提交的 CI 为准。
