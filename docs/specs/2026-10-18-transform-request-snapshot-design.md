# 请求级 Transform 视图

依据 `docs/01` §4.3、§6.5、§11 与 §15.2：一次客户端请求固定 Transform 发布版本、阴影版本和执行预算；配置发布、回滚、解绑或预算调整只影响后续请求。重试仍从原始入站字节分别构造，不把前一次转换产物交给下一站。

在取得选路/Settings 快照时，复用 router 的名称匹配链（含精确耗尽后的前缀候选），从现有 Registry 的一次读锁内复制候选 Route 的不可变版本、绑定和两项预算。未绑定也是固定事实。请求私有视图只读，不是新的进程缓存或权威状态；按实际 Route/Endpoint 惰性编译，坏配置仍按原 Route-local/fail policy 处理，不使无关 Route 的坏版本拖垮整个请求。

发布和阴影的请求、响应、SSE 全部使用该视图。诊断记录继续交给原 Registry，Shadow 不发送额外请求且不改变 live 字节。计时、健康 CAS、认证/模型保护、已提交响应的失败规则不变。

先以真实 HTTP 证明第一站阻塞期间发布/回滚/首次绑定/替换 Shadow 后第二站仍用请求开始版本，且新客户端请求读到新版本；另检查预算与版本同代、无关 Route 不进入视图。随后运行 Transform/代理相关回归、构建和静态检查。
