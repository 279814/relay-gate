# SMTP 强制 TLS

依据已确认的 `docs/01` §13.6、§14.6。当前 `MailConfig` 有 STARTTLS/SMTPS 标志，但发送端直接使用可降级的 `smtp.SendMail`；现有 fake SMTP 测试允许失败后退到捕获函数，不能证明加密连接成立。

沿用 Go 标准库 `net/smtp`，显式管理连接：STARTTLS 必须先确认扩展、完成证书与主机名验证，再认证和发送；SMTPS 从第一个字节即使用 TLS。最小 TLS 版本 1.2，生产使用系统信任根。缺少/冲突的模式、明文服务器、坏证书或握手失败均失败关闭。一次有界截止覆盖连接、握手和整个 SMTP 交互，所有路径关闭自己创建的连接。

Store 保存启用配置前验证唯一 TLS 模式、端口及邮件地址，失败不写入；运行发送端再次验证，保护历史配置和非 HTTP 调用。API 的 I/O 错误继续采用固定错误文本，不回显服务器/密码。UI 提供与现有两个布尔字段一致的显式模式选择，不引入新的配置来源或浏览器存储。

测试邮件使用本次配置直接进行一次真实发送；告警启用状态、严重级别和去重不能制造“已发送”假成功。普通告警继续遵守现有启用、聚合与限速逻辑，SMTP 失败仍不影响真实代理响应。

先写真实 loopback SMTP 回归：明文服务器不能收到 MAIL/DATA；STARTTLS 与 SMTPS 成功必须核对 TLS 上的认证和原始邮件；不可信证书、错误模式和中途断连必须返回失败。现有元数据/去重测试保留，测试 hook 仅证明消息内容，不承担传输安全证明。测试 CA 只由包内测试注入，不增加生产跳过证书验证开关。

本轮不更改数据库 schema。SMTP 聚合窗口/速率可配置及 Security Center 其余要求继续列入完成矩阵，随后分别实现；该项通过不等于整个 P3 或最终发布通过。
