4. **三凭据 UI**（`credentials.mjs`）：Master Key 短时查看、Relay Key 轮换/grace/撤销、管理员密码重置；敏感操作均需当次管理员密码。审计历史来自 SQLite `audit_event`，支持类别、动作、结果、时间和资源筛选及稳定分页，重启后保留。

正式管理审计只存有限动作与原因码、资源标识和不可逆参与者摘要，不存密码、Key、业务正文或原始错误。敏感查看必须先完成持久审计才输出明文；密码/Key 已经变更而终结审计失败时，API 与本地 reset-admin 明确返回已完成、审计待确认，不能把日志失败当成需要再次轮换。遗留未终结记录在重启后显示结果待核实，不驱动重放。

本地 reset-admin、启动轮换前滚/回滚，以及校准成功的 Auth+Recipe 发布也写入同一历史。P4 页面原预算调整环只表示本次运行的细节，正式预算事件仍在持久审计中。尚未实现的 P3 未脱敏证据查看入口不因本审计功能而被宣称完成。

## 旧环境变量部署迁移

停止服务并整体备份 `data/` 后，保留旧环境变量，使用同版本程序执行：

```bash
relay-gate credentials migrate --data-dir /abs/path/data --db /abs/path/data/relay-gate.db
```

确认命令成功后，从 `.env` / 服务启动环境中移除旧 `ENCRYPTION_KEY`、`RELAY_KEYS`、`ADMIN_PASSWORD` 再启动，验证管理员登录与代理。非空环境变量始终优先；保留旧值会覆盖后续 UI 轮换结果。迁移、轮换失败时按 journal 处理，不能直接改密钥文件或删库。

当前样本正文直接以 Master Key 信封加密并在轮换时重封；需求 §5.4 的独立 Sample Data Key 尚未实现，详见 [维护与交接](10-维护与交接.md)。
