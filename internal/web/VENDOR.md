# 第三方前端资源

## alpine.min.js

| 项 | 值 |
|---|---|
| 版本 | Alpine.js 3.14.9 |
| 来源 | `https://cdn.jsdelivr.net/npm/alpinejs@3.14.9/dist/cdn.min.js` |
| 大小 | 44758 字节 |
| SHA256 | `3ED1EED252488921DF65E363D6715DEB04D7F92AAEDB9E52199FDF73CB1E0AD3` |
| 许可 | MIT |

**为什么收录进仓库而不用 CDN**（§6）：这是自托管网关，很可能跑在内网或
访问外网不畅的环境里。首屏依赖 CDN 意味着「网关本身好好的，但管理界面
打不开」—— 而管理界面正是出问题时要用的东西。

**为什么留这份记录**：没有它，日后无法回答「打进二进制的这个文件是不是
官方发布的那个」。核对方式：

```sh
# 期望输出与上表的 SHA256 一致（大小写不敏感）
sha256sum internal/web/static/alpine.min.js
```

`.gitattributes` 里给 `*.js` 定了 `eol=lf`，正是为了让这个哈希在
Windows 检出后仍然对得上 —— 默认的 CRLF 转换会改变文件字节。

**升级步骤**：换掉文件、更新上表的版本/大小/哈希、跑一遍
`go test ./internal/web/`（会校验资源能正常分发），然后手工打开界面确认
交互没坏 —— 界面没有自动化测试（§10.6 已说明这个取舍）。

## 没有构建链

仓库里只有这一个第三方文件，没有 npm、没有打包器。CSS 是手写的
（`app.css`），JS 是一个 Alpine 组件（`app.js`）。这个界面就是几张表格
加表单，一条构建链换不来什么，还会让「改一行样式」变成「先装依赖」。
